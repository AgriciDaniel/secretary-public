# Secretary architecture

Secretary uses one Node controller and two isolated CLI backends. The parent supplies a task file, workspace, optional explicit profile, and run ID. During `prepare`, the controller byte-checks the generated brain manifest against all wiki notes, loads the manifest and Tier 1 files, scores Tier 2 notes deterministically against the task and profile domains, walks the workspace in byte-sorted relative-path order, builds one hashed evidence manifest, and assembles a frozen prompt. During `run`, it verifies the prepared hashes, performs an active preflight, then starts the selected CLI in a dedicated process group.

The controller also owns a separate personalization boundary under private state. A first-run console records only an explicit persistence decision and confirmed allowlisted presentation preferences. Consent and preferences have separate closed schemas and revisions. Session-only setup writes nothing. A remembered decline stores no preferences. The generated brain is never rewritten from conversation history, and raw conversations are not retained as personalization.

When provider use is consented and personalization is active, `prepare` freezes an allowlisted snapshot no larger than 4096 bytes, records its hash in run metadata, and inserts it after the profile as untrusted advisory data. The current explicit instruction outranks it, and it cannot change evidence, authority, approval, dissent, retention, or security rules. Without provider consent, or when state is paused, declined, corrupt, or unknown, no personalization bytes enter the provider prompt. An explicit `--profile` outranks a saved default profile.

Brain retrieval has three layers. Tier 0 is the generated manifest containing every note path, title, domain, confidence tag, tags, and one-line operating summary. Tier 1 is the profile's `always_load` set, including the root routing notes, conventions, confidence vocabulary, frozen claim-evidence registry, every domain hub, and the gaps and questions hubs. Tier 2 contains positive-scoring leaf notes, ordered by score and then byte-sorted path. Title, tag, domain, operating-summary, task, and configured profile-domain matches determine the score. When a selected note has claim-evidence rows, its frozen raw extracts are loaded with it. A note and its extracts are admitted only when the full group fits the brain token budget. `max_notes` and `max_note_tokens` bound selection. The token budget includes Tier 0, Tier 1, Tier 2, and associated extract content and uses the ceiling of UTF-8 bytes divided by four for each file.

General evidence loading is bounded by `max_evidence_file_bytes`, `max_evidence_total_bytes`, and `max_evidence_files` in the selected profile. Brain entries lead the sequence and share one cap budget with workspace entries. Text files are content-sniffed and supplied behind per-content hash delimiters. Binary files and special files are manifested but omitted. Symlinks are manifested but never followed, and their hashes cover link text rather than target contents. Cap truncation and every skipped file are disclosed in the prompt and in a controller-bound result field. The controller rejects a result that changes that disclosure. The brain retrieval notice separately lists every note body not loaded for the task.

The exact assembled prompt is stored as `prompt.md` with mode 0600. Its hash, task hash, evidence manifest hash, and delimiter identifiers are stored in `prompt-metadata.json`. The result schema used to build and validate the run is also frozen in the run directory. This makes the model's actual knowledge snapshot auditable after the workspace changes.

Run state lives under `${XDG_STATE_HOME:-$HOME/.local/state}/secretary/`. Directories use mode 0700. Files use mode 0600 and are replaced atomically. Runs older than 30 days are retained only until the next controller maintenance pass.

Backend output is untrusted. The controller derives a wire schema from the frozen full schema by removing JSON Schema metadata and top-level combinators that the CLI APIs reject. Claude receives that derived schema inline through `--json-schema`. Codex receives the same derived schema as a private file through `--output-schema`. The frozen full schema validates every returned object locally after the run, including the `needs_approval` conditional. Additional integrity checks require exact evidence disclosure, bind citations to loaded brain note bodies and URLs, constrain high confidence to complete raw evidence plus human support, and prevent a silent `completed` result when reported contradictions or unverified claims require dissent.

No child receives file tools. Claude is invoked with an empty tool list and a neutral state directory. Codex also starts in the neutral directory. All brain and workspace evidence reaches either backend only through the prepared prompt, where both origins remain hash-delimited untrusted data.

Claude must exit zero and return a JSON result envelope with `is_error: false` and its own top-level `structured_output`. Codex JSONL must reach `turn.completed`; a preceding error item is diagnostic, while `turn.failed` is fatal. A status, timer, monitor, `waiting` event, or expected delegated report is never completion. Its final agent message must itself be a JSON object. Both paths are normalized to the same fail-closed result envelope before full local validation against `schemas/run-result.json`.

Every result includes a `quality_control` record with fit, acceptance criteria, outcome, stop reason, and review status. `passed` cannot coexist with unverified claims. When independent review is required, same-context self-review cannot satisfy it. The current controller runs one child context and does not autonomously spawn research subagents or a second critic. Fresh-context and human review remain explicit external gates rather than simulated independence.

The file-backed Gauntlet lane is a separate controller boundary under `quality`. `freeze` validates `schemas/quality-job.v1.json`, verifies and copies a hash-bound workspace baseline and reference, and enforces protected gates, at least one blocking deterministic gate, hard resource ceilings, coupling-aware scheduling, fresh-context artifact review, and zero inherited external authority. It stores the canonical job hash in private state.

`packet` freezes a bounded regular artifact contained by the frozen workspace and binds an iteration commitment to the job hash and one declared builder. `review` validates `schemas/quality-review-result.v1.json` and rejects self-sign-off, stale baseline, reference, or artifact hashes, mismatched gate or dimension sets, unmet reviewer policy, false weighted scores, inconsistent deterministic exit codes, and an internally inconsistent `passed` recommendation. Gate evidence files are size-bounded, workspace-contained, hash-checked, and copied into private iteration state. `status` rechecks packet, artifact, review, evidence-manifest, and frozen-evidence commitments before deriving improvement, regression, plateau, budget, inconclusive, and human-adjudication outcomes. The lane never invokes a builder, reviewer, provider, or tool. Builder identity, reviewer independence, inspection, exit codes, and resource usage remain declared provenance, not cryptographically authenticated facts. Therefore a reviewer-reported pass cannot become controller-certified acceptance and terminates at `needs_human_decision`.

Cancellation signals the dedicated process group, waits for a bounded grace period, escalates to SIGKILL when needed, and verifies that the group has no remaining processes. This mechanism requires POSIX process-group signals. Windows cancellation is explicitly unsupported and fails loudly.

An action-capable result halts at `needs_approval`. The action type, target, and content hash are bound into one action hash. Each prepared run has a private random HMAC key. A human grant binds the run, approval ID, typed action, expiry, and allowed root, then stores the signed grant in private run state. Non-interactive approval must repeat the displayed action hash as a confirmation guard.

Execution verifies the grant HMAC, action hash, grant hash, expiry, and supplied content hash before consuming the approved state revision. Exclusive revision claims give exactly one concurrent consumer the right to transition to `executing`. The controller stages the verified content and records the complete execution intent before dispatching to the `file.write` adapter. It never retries a consumed grant silently. The adapter has no shell capability and enforces the allowed-root boundary.

Generated instruction surfaces derive from `contracts/secretary-core.md`. The generated brain manifest derives from every Markdown file under `wiki/`. After changing either source, run `npm run generate`, then run `node scripts/check-generated.mjs`.

Installed instruction surfaces receive a Secretary ownership marker and a validated link to the source checkout's controller. Before any installed file is replaced, the installer checks every collision and rejects unowned content. Parent path components are inspected directly, and a symlink or non-directory component fails installation before writes begin. The linked controller itself must be a regular, non-symlinked file inside the real source root. Relocating the source checkout makes the installed link stale by design. The Markdown surface instructs the host to stop and request reinstallation instead of searching for a different executable. Static tests verify the record and instruction; behavioral host evaluation is still required to prove compliance.

The installer also writes a target-local `secretary.install-manifest/1` record containing the exact allowlisted installed paths, their kinds, and their SHA-256 hashes. Uninstall first validates the entire manifest and every present surface, then removes only the three canonical surfaces, an installed exact `chief-of-staff` alias, and the manifest itself. Marker loss, content drift, unknown paths, and symlinks fail before deletion. Missing manifested files are reported, and directories or unrelated host files are not removed. Removal does not depend on the source checkout remaining at its recorded location. Both installation and removal remain vulnerable to a malicious same-user process that wins a path-replacement race after validation.

The canonical full-suite command is `npm test`. The deterministic runner enumerates only `tests/**/*.test.mjs`, rejects symlinks in that tree, and passes the sorted file list to Node with test concurrency set to one. Ignored release projections cannot enter canonical discovery. Process-group cancellation tests therefore run serially so their signal and descendant assertions are isolated from parallel test workers.

Public CI runs the full test and static gate sequence on Ubuntu with Node 20 and Node 24, plus macOS with Node 24. Feature-branch pushes are not run separately when a pull request already supplies the verification event. Push verification is limited to `main`, and superseded runs for the same pull request or ref are cancelled. The macOS lane proves the checked-in offline suite on a GitHub-hosted macOS image. It does not prove every macOS version, local shell, installed Claude or Codex runtime, provider account, network path, or live model behavior.
