# Support

Choose the channel that matches the question. Do not put credentials, private
client data, account content, or sensitive vulnerability details into a public
issue or community post.

## Documentation

- Start with [README.md](README.md) for scope, installation, status, and the
  verification matrix.
- Use [docs/cli.md](docs/cli.md) for commands, run state, approvals, and backend
  boundaries.
- Use [docs/architecture.md](docs/architecture.md) for the trust and data-flow
  model.
- Use [RELEASE_NOTES.md](RELEASE_NOTES.md) for the current preview and open
  release gates.
- Use [CONTRIBUTING.md](CONTRIBUTING.md) before proposing code, documentation,
  profile, or research changes.

## GitHub Issues

Use the public repository's Issues tab for:

- A reproducible bug in Secretary code or documentation.
- A focused feature request with a clear authority and safety boundary.
- A source, citation, taxonomy, or rights correction with an exact locator.

Include the command, expected result, actual result, operating system, Node.js
version, backend name, and the smallest safe reproduction. Redact task content,
prompts, account data, local paths, and provider credentials.

## Community

- [Free AI Marketing Hub](https://www.skool.com/ai-marketing-hub): open learning,
  general questions, shared workflows, and community discussion.
- [AI Marketing Hub Pro](https://www.skool.com/ai-marketing-hub-pro): private
  community, live sessions, advanced workflows, and Pro resources.

Community discussion is not a support guarantee and cannot authorize changes to
Secretary, a provider account, a local machine, or a third-party system.

## Security

Follow [SECURITY.md](SECURITY.md) for a suspected vulnerability. Sensitive
reports belong in the repository's private vulnerability-reporting channel, not
GitHub Issues or either community.

## Provider and account boundaries

Secretary does not operate Anthropic, OpenAI, Skool, GitHub, or Printing Press.
Questions about provider billing, quotas, account recovery, terms, or service
availability belong with the relevant provider. Never share a live credential
for troubleshooting.
