# Branches and Sequels

## Operating Summary

A branch is a contingency option already built into a base plan for changed conditions.
A sequel is a subsequent operation selected from possible outcomes of the current operation.
For significant scheduled work, the digest encodes one branch for the most likely disruption.
It also encodes sequels for success, failure, and stalemate.

## Source-Led Facts

- ADP 5-0 defines a branch as a contingency option within the base plan ([Army Publishing Directorate](https://armypubs.army.mil)).
- A branch responds to changed conditions ([Army Publishing Directorate](https://armypubs.army.mil)).
- ADP 5-0 defines a sequel as a subsequent operation ([Army Publishing Directorate](https://armypubs.army.mil)).
- The sequel depends on possible outcomes of the current operation ([Army Publishing Directorate](https://armypubs.army.mil)).
- The digest encodes a most-likely-disruption branch for every significant scheduled item.
- The digest encodes sequels for success, failure, and stalemate.
- The digest presents this as the concrete mechanism for anticipating needs 72 hours ahead.

## Operating Procedure

The following is digest-labelled encoding, not a verbatim Army planning process.

1. Identify the significant scheduled item.
2. State its intended outcome.
3. Name the current base plan.
4. Identify the most likely disruption.
5. Define the changed condition that activates a branch.
6. Prepare one branch for that condition.
7. Keep the branch actionable.
8. Identify what information would reveal the condition.
9. Consider nominating that information under [[escalation/CCIR]].
10. Define the success outcome.
11. Prepare the success sequel.
12. Define the failure outcome.
13. Prepare the failure sequel.
14. Define the stalemate outcome.
15. Prepare the stalemate sequel.
16. Name the owner of each follow-on action.
17. Check authority before external action.
18. Apply [[judgment/Reversibility as the Master Gate]] to each branch and sequel.
19. Brief the plan with [[communication/I-PASS Briefing Schema]].
20. Review when conditions change.

### Anticipation questions

What is likely to change before execution?
What observation would reveal that change?
What can be prepared without committing the principal?
What follows if the current action succeeds?
What follows if it fails?
What follows if it neither succeeds nor fails?

## Boundaries

- A branch is tied to changed conditions, not every imaginable event.
- A sequel follows an outcome, not a vague future wish.
- The one-branch encoding prioritizes the most likely disruption.
- The three sequel categories are an encoding supplied by the digest.
- Preparation does not imply authorization to execute.
- No branch may exceed [[ethics/Agency Authority Boundaries]].
- A branch trigger may belong in [[escalation/Threshold Design]].
- A reporting trigger may be nominated under [[escalation/CCIR]], but the principal designates it.
